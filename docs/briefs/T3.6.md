Contract:

```ts
/** Items an order of this kind may ask for: discovered, in an ingredient or baked chain, tier <= the kind's maxTier. */
export function orderCandidates(
  data: GameData,
  state: GameState,
  kind: CustomerKind,
): Item[];
/**
 * True when the item is discovered, in an ingredient chain, and some generator that is on the
 * board (not cobwebbed) or in the Pantry has a spawn table containing an item of that chain.
 */
export function isProducible(
  data: GameData,
  state: GameState,
  itemId: ItemId,
): boolean;
/** The first task in the current chapter, in order, that isn't complete and whose prerequisites are. Null when none. */
export function nextTask(
  data: GameData,
  state: GameState,
): RenovationTask | null;
/** A new order with id state.nextOrderId. Doesn't change state; the caller adds it. */
export function generateOrder(
  data: GameData,
  state: GameState,
  rng: Rng,
): Order;
/** The tick handler. See "Refilling" below. */
export function refillOrders(
  data: GameData,
  state: GameState,
  rng: Rng,
  now: Timestamp,
): ActionResult;
```

**generateOrder**, in this order, so the same seed always gives the same order:

1. Customer: eligible = customers with no open order (if that leaves none of a kind, use all of that kind). Regulars are the ids in `state.unlockedCustomers`. If any eligible regular exists and `rng.next() × 100 < regularChancePercent`, pick a regular uniformly with `rng`; otherwise pick a walk-in uniformly. Throw if there are no walk-ins.
2. Rules = `economy.orders.regular` or `.walkIn`. Item count = a uniform integer in [minItems, maxItems].
3. Candidates = `orderCandidates` for the kind. If no open order has every wanted item producible, keep only producible candidates, so at least one open order is always fillable. Throw if no candidates remain.
4. Weights: 1 per candidate, × `featuredWeight` if `nextTask` lists it in `featuredItems`, × `featuredWeight` again if the customer lists it as a favorite. Pick each item with `weightedPick`; repeats are allowed.
5. Reward: coins = round(sum of sellValue × coinMultiplier); stars = `starsByItemCount[count − 1]`; xp = sum of tier × `xpPerTier`.

**Refilling:** if `nextOrderAt` is null or `now < nextOrderAt`, return the same state and no events. Otherwise generate orders one at a time until there are `maxOpen`, each seeing the orders before it, incrementing `nextOrderId` and emitting `orderArrived` for each; then set `nextOrderAt` to null.

Rules: pure functions in src/core; no edits to types.ts; follow docs/briefs/working-rules.md. Chapter 1 has no renovation tasks yet, so test `nextTask` and featured weighting with a copy of `testData` whose chapter has tasks.

Done when: `npx vitest run src/core/orders.test.ts` passes, including checks over 500 seeded orders that: item counts stay in bounds; every wanted item is discovered, in an ingredient or baked chain, and within maxTier; rewards match the formula; after each refill at least one open order is fully producible; featured and favorite items come up more often than others; regulars appear at about `regularChancePercent` when unlocked and never when none are; the same seed gives the same orders. Also test refilling: not yet due, due with 0 and with 3 open orders, and the id counter. The checks in working-rules.md pass.
