# Task T4.1: Loading a recipe into an oven

Context: Rise & Shine Bakery, a browser merge game (TypeScript, Vite, PixiJS, Vitest).
Read first: src/core/types.ts (`Bake`, `BakeSlotRef`, `OvenState`, `Recipe`, `OvenDef`, `ActionResult`, `GameEvent`), src/core/board.ts, src/core/testing.ts, src/data/recipes.json, src/data/ovens.json, docs/briefs/working-rules.md.

Goal: Move a recipe's ingredients from the board into a free oven slot and start the bake timer.

Files to create or edit: src/core/kitchen.ts, src/core/kitchen.test.ts. Do not edit any other file.
Contract:

```ts
/** The bake in a slot, or null when empty. Throws RangeError for an oven or slot index that doesn't exist. */
export function getBake(state: GameState, slot: BakeSlotRef): Bake | null;
/** A new state with that one slot replaced. Throws RangeError like getBake. */
export function setBake(
  state: GameState,
  slot: BakeSlotRef,
  bake: Bake | null,
): GameState;
/** recipe.bakeSec × 1000 × the oven's bakeTimeMultiplier, rounded to whole ms. Throws on unknown ids. */
export function bakeDurationMs(
  data: GameData,
  recipeId: RecipeId,
  ovenId: OvenId,
): number;
/**
 * Throws for an unknown recipe, a bad slot, or `cells` whose length differs from the recipe's
 * inputs or that repeats a cell (programming errors: the UI builds `cells`).
 * Rejects 'slotBusy' when the slot holds a bake, and 'missingItems' when any cells[i] doesn't
 * hold recipe.inputs[i] (empty, locked, a different item, or cobwebbed).
 * Otherwise empties those cells and sets the slot to
 * { recipeId, startedAt: now, endsAt: now + bakeDurationMs(recipe, the slot's oven) }.
 * Event: bakeStarted { slot, recipeId }.
 */
export function loadRecipe(
  data: GameData,
  state: GameState,
  slot: BakeSlotRef,
  recipeId: RecipeId,
  cells: readonly CellIndex[],
  now: Timestamp,
): ActionResult;
```

A new game has one Toaster Oven with one slot. To test a Brick Oven's multiplier, pass `kitchen: { ovens: [{ ovenId: 'brick-oven', slots: [null, null] }] }` to `stateWith`.

Rules: pure functions in src/core; no edits to types.ts; follow docs/briefs/working-rules.md.

Done when: `npx vitest run src/core/kitchen.test.ts` passes, with tests for: a successful Croissant load (both cells emptied, `endsAt` = now + 300 000 in a Toaster Oven, `bakeStarted` event); the Brick Oven's 0.8 multiplier; a busy slot; each kind of missing input (empty cell, wrong item, cobwebbed item, locked cell); a bad slot, a wrong-length `cells`, and a repeated cell each throwing; `getBake`/`setBake` not mutating their input. The checks in working-rules.md pass.
If the contract seems wrong, stop and explain instead of changing it.
