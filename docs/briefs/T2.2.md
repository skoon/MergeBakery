# Task T2.2: Merge rules and discovery

Context: Rise & Shine Bakery, a browser merge game (TypeScript, Vite, PixiJS, Vitest).
Read first: src/core/types.ts (`Item`, `GameData`, `GameState`, `GameEvent`), src/core/data.ts (`loadGameData`), docs/briefs/working-rules.md.

Goal: Decide when two items merge and what they become, and record newly made items for the Recipe Book.

Files to create or edit: src/core/merge.ts, src/core/merge.test.ts, src/core/discovery.ts, src/core/discovery.test.ts. Do not edit any other file.
Contract:

```ts
// merge.ts
/** The item one tier up in the same chain, or null at the chain's top tier. Throws on an unknown id. */
export function nextTier(data: GameData, itemId: ItemId): Item | null;
/** True when a and b are the same item and it has a next tier. The Golden Whisk is handled elsewhere (T3.3). */
export function canMerge(data: GameData, a: ItemId, b: ItemId): boolean;

// discovery.ts
/**
 * Records that an item was made. If it is new, appends it to `discovered` and
 * `pendingDiscoveries` and returns a `discovered` event. Otherwise returns the
 * same state object and no events. Throws on an unknown id.
 */
export function discover(
  data: GameData,
  state: GameState,
  itemId: ItemId,
): { state: GameState; events: GameEvent[] };
```

Use `data.chainItems` to find the next tier. Tests use the real data from `loadGameData()` and a state from `createNewGame(data, 1, 0)` (src/core/newGame.ts).

Rules: pure functions in src/core; no edits to types.ts; follow docs/briefs/working-rules.md.

Done when: `npx vitest run src/core/merge.test.ts src/core/discovery.test.ts` passes, with tests showing: two identical items merge; different items don't; top-tier items (`sourdough-boule`, `flour-mill-3`) and single-tier items (`energy-jar`, `golden-whisk`) don't; `nextTier` walks a whole chain and throws on an unknown id; `discover` adds a new item once, returns the same state for a known item, and doesn't mutate its input. The checks in working-rules.md pass.
If the contract seems wrong, stop and explain instead of changing it.
