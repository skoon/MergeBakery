# Task T4.5: Save format and storage

Context: Rise & Shine Bakery, a browser merge game (TypeScript, Vite, PixiJS, Vitest, zod 4).
Read first: src/core/types.ts (all of `GameState` and what it contains), src/core/data.ts (how its zod schemas are written and typed against types.ts), src/core/newGame.ts, src/core/testing.ts, docs/briefs/working-rules.md.

Goal: Turn a game state into a versioned save string and back, rejecting anything corrupt, and read and write it in browser storage without ever crashing the game.

Files to create or edit: src/core/save.ts, src/core/save.test.ts, src/ui/saveStorage.ts, src/ui/saveStorage.test.ts. Do not edit any other file.
Contract:

```ts
// src/core/save.ts (pure: no storage access)
export const SAVE_VERSION = 1;
export interface SaveFile {
  version: number;
  savedAt: Timestamp;
  state: GameState;
}
export type LoadResult =
  { ok: true; save: SaveFile } | { ok: false; error: string };
/** JSON of { version: SAVE_VERSION, savedAt, state }. */
export function serializeSave(state: GameState, savedAt: Timestamp): string;
/**
 * Never throws for bad input. Errors (ok: false, with a message saying what failed): not JSON;
 * not an object with a numeric `version`; a version newer than SAVE_VERSION; a `state` that
 * doesn't match GameState exactly (strict zod schema typed as z.ZodType<GameState>, like
 * data.ts); an item, oven, recipe, customer, or chapter id unknown to `data`; a board whose
 * cols, rows, or cell count differ from data.newGame.
 */
export function deserializeSave(data: GameData, text: string): LoadResult;

// src/ui/saveStorage.ts
export const SAVE_KEY = 'rise-and-shine-save';
/** The part of the Web Storage API used here; window.localStorage satisfies it. */
export interface KeyValueStorage {
  getItem(key: string): string | null;
  setItem(key: string, value: string): void;
}
/** Writes serializeSave(state, now) to SAVE_KEY. If storage throws (full, disabled), logs with console.error and returns false. */
export function writeSave(
  storage: KeyValueStorage,
  state: GameState,
  now: Timestamp,
): boolean;
/**
 * Reads SAVE_KEY. No save: null. A save that fails deserializeSave: copied as-is to
 * `${SAVE_KEY}-corrupt-${now}`, logged with console.error including the error, and null
 * returned so the caller starts a new game. Storage that throws on read: console.error, null.
 */
export function readSave(
  storage: KeyValueStorage,
  data: GameData,
  now: Timestamp,
): SaveFile | null;
```

Rules: pure functions in src/core; no edits to types.ts; follow docs/briefs/working-rules.md. Tests use an in-memory `KeyValueStorage` built on a `Map`, and spy on `console.error` so the output stays quiet.

Done when: `npx vitest run src/core/save.test.ts src/ui/saveStorage.test.ts` passes, with tests for: a round trip that gives an equal state (`toEqual`) for a new game and for a busy state (pantry items, orders, a running bake, lastSale, cobwebbed and locked cells, a generator on cooldown); each error case above; `readSave` with no save, a good save, a corrupt save (backup key written, null returned), and a throwing storage; `writeSave` with a throwing storage (false). The checks in working-rules.md pass.
If the contract seems wrong, stop and explain instead of changing it.
