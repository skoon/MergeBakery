# Task T1.8: New game and dispatch skeleton

Context: Rise & Shine Bakery, a browser merge game (TypeScript, Vite, PixiJS, Vitest).
Read first: src/core/types.ts (`NewGameConfig`, `GameState`, `Action`, `ActionResult`, `Dispatch`, `Rng`), src/core/rng.ts (T1.9's `createRng`), docs/briefs/phase-1-ids.md.

Goal: Define the starting board in data, build a fresh `GameState` from it, and add the reducer that routes each action to a handler.

Files to create or edit: src/data/newGame.json, src/core/newGame.ts, src/core/newGame.test.ts, src/core/dispatch.ts, src/core/dispatch.test.ts. Do not edit any other file.
Contract:

```ts
// newGame.ts
export function createNewGame(
  data: GameData,
  seed: number,
  now: Timestamp,
): GameState;

// dispatch.ts
export type Handlers = {
  [T in ActionType]: (
    data: GameData,
    state: GameState,
    action: Extract<Action, { type: T }>,
    rng: Rng,
  ) => ActionResult;
};
export function createDispatch(handlers: Handlers): Dispatch;
export const dispatch: Dispatch; // createDispatch with a stub for every action type
```

newGame.json is a `NewGameConfig` with these values:

- `cols` 7, `rows` 9 (63 cells, row-major: index = row × 7 + col)
- `locks`: cells 42–48 are `crate`; cells 49–62 are `flourSack`
- `items`: `flour-mill-1` at 23, `dairy-fridge-1` at 25, `wheat-stalk` at 30, `milk-splash` at 32, all with `cobwebbed: false`; `wheat-bundle` at 36 and `milk-bottle` at 40 with `cobwebbed: true`
- `ovens` [`toaster-oven`], `coins` 50, `gems` 10, `chapterId` `chapter1`, `unlockedCustomers` []

`createNewGame` returns:

- `board`: `cols × rows` cells from the config; unlisted cells are `{ kind: 'empty' }`. Each item is a `BoardItem` whose `generator` is `{ charges: <its GeneratorDef's charges>, cooldownEndsAt: null }` for generator items and `null` otherwise.
- `pantry`: `{ capacity: economy.pantry.startSlots, items: [] }`
- `energy`: `{ value: economy.energy.cap, updatedAt: now }`
- `coins` and `gems` from the config; `stars` 0, `xp` 0, `level` 1
- `orders` [], `nextOrderAt` `now` (so the first tick brings orders)
- `kitchen.ovens`: one `OvenState` per config oven, with `slots` filled with `null` up to the oven's slot count
- `lastSale` null; `discovered`: the starting items' ids, deduplicated, in cell order; `pendingDiscoveries` []; `rewardedChains` []
- `chapterId` and `unlockedCustomers` from the config; `completedTasks` []; `tutorialStep` `firstTap`
- `rngState`: `seed >>> 0`; `nextOrderId` 1

`createDispatch(handlers)` returns a `Dispatch` that builds `createRng(state.rngState)`, calls the handler for `action.type`, and on `ok: true` returns the handler's result with `state.rngState` set to `rng.getState()`. It returns `ok: false` results unchanged. Every stub in `dispatch` throws `Error('Not implemented: <type>')`. The `Handlers` mapped type makes a missing action type a compile error.

Rules: pure functions in src/core; no new dependencies; no edits to types.ts. The data loader (T1.7) is being written at the same time, so tests build their own small `GameData` fixture inline with just the maps they need (items, generators, ovens, economy, newGame); don't import src/core/data.ts. Other sessions are editing other files in this folder: don't run git commands, `npm install`, or `npm run format`; format and lint only your files with `npx prettier --write <files>` and `npx eslint <files>`.
