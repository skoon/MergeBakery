# Task T5.11: Sound effects

Context: Rise & Shine Bakery, a browser merge game (TypeScript, Vite, PixiJS, Vitest).
Read first: src/audio/audioManager.ts and src/audio/mergeChime.ts (T5.10: `ToneSpec`, `play`), src/core/types.ts (`GameEvent`), src/ui/bakeNotifier.ts (`finishedBakes`), src/ui/store.ts, src/core/data.ts (zod validation), src/main.ts, the GDD's Audio section (docs/), docs/briefs/working-rules.md.

Goal: Every sound the GDD lists plays at the right moment, each defined in one data file so sounds can be retuned without touching code.

Starts after T5.10.

Files to create or edit: src/data/sfx.json, src/audio/sfx.ts, src/audio/sfx.test.ts, src/main.ts (one line). Do not edit any other file.

There are no audio files: each sound is a short list of synthesized tones (`ToneSpec` from T5.10).

## Contract

```ts
// src/audio/sfx.ts
export type SoundId =
  | 'tap' // generator tap: a soft thunk
  | 'deliver' // order complete: a shop bell, then a coin jingle
  | 'ovenDone' // a bake finishes: a kitchen-timer ding
  | 'renovation' // a task completes: a short brass sting
  | 'sell'
  | 'collect' // tapping a bonus item
  | 'discover'
  | 'levelUp';

/**
 * sfx.json: `{ "sounds": { [id]: ToneSpec[] } }` with optional per-chain tap variants
 * `"tap.<chainId>"` (the GDD's flour puff, egg clack, fridge hum), keyed by the chain of the
 * item a tap spawned. Validated with zod: every SoundId present, each list non-empty,
 * frequencies 20–8000 Hz, gains 0–1, durations 1–2000 ms. Throws one Error listing every problem.
 */
export function parseSfx(
  raw: unknown,
): Readonly<Record<string, readonly ToneSpec[]>>;

/** The tones for an event, or null when it has no sound. Merges are T5.10's chime, not here. */
export function soundForEvent(
  data: GameData,
  sfx: Readonly<Record<string, readonly ToneSpec[]>>,
  event: GameEvent,
): readonly ToneSpec[] | null;

/**
 * Plays soundForEvent for each event after every store notification, and 'ovenDone' when a
 * bake finishes (checked each second with finishedBakes, each bake once, whether or not the
 * tab is visible — the browser mutes a hidden tab anyway). Returns a stop function.
 */
export function startSfx(
  store: GameStore,
  audio: AudioManager,
  clock: () => Timestamp,
  sfx: Readonly<Record<string, readonly ToneSpec[]>>,
): () => void;
```

## Event mapping

`spawned` with `rare: false` → `tap.<chain>` if present, else `tap`; `spawned` with `rare: true` → `tap` then `discover`'s tones; `orderDelivered` → `deliver`; `taskCompleted` → `renovation`; `sold` → `sell`; `collected` → `collect`; `discovered` → `discover`; `levelUp` → `levelUp`. Every other event → null.

## Writing the sounds

Keep them gentle, per the GDD ("never nagging"): peak gains 0.15–0.4, nothing over 600 ms except `renovation` (up to 900 ms). Rough starting points: `tap` a 110 Hz triangle for 70 ms; `deliver` two bright sines a fourth apart, then three quick high notes; `ovenDone` two 1320 Hz sines 150 ms apart; `renovation` a rising major triad on sawtooth at low gain. Include `tap.flour`, `tap.dairy`, `tap.egg` and `tap.sugar` variants. Scott tunes them by ear in the review.

In main.ts, load `src/data/sfx.json` through `parseSfx` and call `startSfx(store, audio, () => Date.now(), sfx)` beside `startMergeChime`.

Rules: no edits to types.ts; follow docs/briefs/working-rules.md. Test with T5.10's fake audio context approach or a fake `AudioManager` that records `play` calls.

Done when: `npx vitest run src/audio/sfx.test.ts` passes, with tests for: the real sfx.json parsing; each validation problem, all in one error; every row of the event mapping, including a per-chain tap and the fallback; `startSfx` playing on store events, playing `ovenDone` once when a bake finishes, and stopping. `npm run build` succeeds (delete dist/ afterwards). The checks in working-rules.md pass. The phase-end review hears every GDD sound event in a browser.
If the contract seems wrong, stop and explain instead of changing it.
