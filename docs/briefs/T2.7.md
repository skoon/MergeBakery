# Task T2.7: Placeholder item art

Context: Rise & Shine Bakery, a browser merge game (TypeScript, Vite, PixiJS, Vitest).
Read first: src/core/types.ts (`Item`, `Chain`), src/data/items.json, docs/briefs/working-rules.md.

Goal: Generate one placeholder SVG per item so the board is playable before the final art (T5.14).

Files to create or edit: scripts/gen-placeholder-art.js, package.json (add one script), public/art/<spriteKey>.svg for every item (generated), src/render/art.test.ts. Do not edit any other file.
Contract:

- `scripts/gen-placeholder-art.js` is a plain Node ES module (the package is `"type": "module"`) using only `node:fs` and `node:path`. It reads src/data/items.json and writes `public/art/<spriteKey>.svg` for every item, overwriting existing files. It never deletes files.
- Add `"art:placeholders": "node scripts/gen-placeholder-art.js"` to package.json `scripts`. Change nothing else in package.json.
- Each SVG is 128 × 128 (`width`, `height`, and `viewBox="0 0 128 128"`): a rounded square (corner radius 24) filled with the item's chain color and a 4 px darker outline; the tier number large and bold in the center; below it, a short label of up to 3 capital letters from the item name's words (Wheat stalk → WS, Crème brûlée → CB). Text is white on dark colors and near-black on light colors, choosing by the color's relative luminance.
- Run the script once so the SVGs exist.
- The test lists the art files with `Object.keys(import.meta.glob('/public/art/*.svg'))` (this works under Vitest; don't use `node:fs` in tests) and checks every item's `spriteKey` in `loadGameData()` (src/core/data.ts) has a file.

Rules: no new dependencies; no edits to types.ts; follow docs/briefs/working-rules.md. Also lint the script: `npx eslint scripts/gen-placeholder-art.js`.

Done when: `npm run art:placeholders` writes 54 files, and `npx vitest run src/render/art.test.ts` passes. The checks in working-rules.md pass.
If the contract seems wrong, stop and explain instead of changing it.
