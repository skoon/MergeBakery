# Task T14.7: Building and deploying season packs

Context: Rise & Shine Bakery, a browser merge game (TypeScript, Vite, PixiJS, Vitest).
Read first: `implementation_plan.md` section 1 ("Where a pack lives", "Offline"), `docs/briefs/T14.6.md` ("The catalog"), `src/seasons/pack.ts`, `src/seasons/loader.ts`, `scripts/gen-placeholder-art.js`, `vite.config.ts`, `eslint.config.js`, docs/briefs/working-rules.md.

Goal: a season's source lives in `seasons/<id>/`; `npm run build:seasons` validates every pack against the base game and writes the deployable files to `public/seasons/` (a build output, gitignored), including `index.json` in T14.6's format. `npm run dev` and `npm run build` run it first, so the GitHub Pages deploy ships the packs. The service worker caches packs at runtime instead of precaching them. No pack content (T14.9) and no season UI (T14.8).

Branch: `t14.7-pack-build` (off `t14.6-runtime-loading`). Built in the same uncommitted working tree as T14.6; the Files table is the split for the commit.

## Source layout: `seasons/<id>/`

| File                | Required | What                                                                                                                                         |
| ------------------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `season.json`       | yes      | The pack (`pack.ts` format). The folder name must equal its `id`.                                                                            |
| `placeholders.json` | yes      | `{ "<spriteKey>": "<emoji>" }` for every item and keepsake sprite key without drawn art; one to three emoji (T14.10: "🍒🍒🍒" for a handful) |
| `art/<key>.png`     | no       | Drawn art; each file name must be one of the pack's sprite keys                                                                              |
| `art/<key>.svg`     | no       | A drawing laid on the placeholder tile, under the tier number (T14.10): one `<svg viewBox="0 0 128 128">` element, for a key with no emoji   |
| `rules.ts`          | no       | Default-exports the pack's `SeasonRules`; may only `import type` from the game                                                               |
| `rules.test.ts`     | no       | Its tests (Vitest, may import the game freely)                                                                                               |
| `scenes.json`       | no       | Read by T14.8                                                                                                                                |

`seasons/keepsakes.json` (committed, written by the build) records every season built and its keepsakes' sprite keys.

## Output: `public/seasons/`

`index.json`: `{ "seasons": [ ...one entry per pack, sorted by id ] }`, each entry `{ id, name, version, window, apiVersion, rules, pngKeys }` exactly as `loader.ts` reads it; `{ "seasons": [] }` with no packs. Per pack, `<id>/<version>/`: `season.json` (copied byte for byte), `rules.js` when there is a `rules.ts`, and `art/` with every `.png` plus a generated `.svg` (the tile with its emoji or drawing) for every other sprite key.

## Decisions (defaults, recorded under /goal)

1. **Validation runs the game's own code.** The script starts Vite in middleware mode and `ssrLoadModule`s `src/seasons/build.ts`, which calls `loadGameData()` and `parseSeasonPack`, so a pack that the game would skip fails the build instead. Every problem in every pack is listed in one error; the script exits 1.
2. **`rules.ts` compiles with Vite's library mode** (ES module, one file, no externals) to `rules.js`, which the script then imports and checks with the loader's own `checkRules`. A lint rule (`@typescript-eslint/no-restricted-imports`, type imports allowed) stops `rules.ts` importing anything at runtime except files in its own folder, so no game code is copied into a pack.
3. **Placeholder SVGs** match the base placeholders (128×128, rounded tile in the chain's colour with a darker outline) with the emoji in the middle (two side by side, three in a cluster) and the tier in the top-left corner. Keepsakes have no chain: a fixed gold tile and no tier. A drawing (`art/<key>.svg`, T14.10) takes the emoji's place on the same tile. A sprite key with no `.png`, no drawing and no emoji, an emoji for a key the pack doesn't have, a `.png` or `.svg` that isn't a sprite key, a key with more than one of `.png`, `.svg` and an emoji, a drawing that isn't one `<svg viewBox="0 0 128 128">` element, more than three emoji for a key, or a sprite key that isn't a safe file name (`[a-zA-Z0-9_-]`) fails the build.
4. **Keepsakes keep their art.** A `KeepsakeRecord` stores its sprite key forever, and its art is served from the season's current version folder. `seasons/keepsakes.json` maps each season built to the keepsake sprite keys it has ever had. The build fails if a recorded season has no source folder (so every season stays in the index) or a recorded key is no longer one of the pack's keepsake sprite keys. A new season or keepsake is added to the record and the script says so; on CI (`CI` set, as on GitHub Actions) a missing record entry fails instead ("run `npm run build:seasons` and commit `seasons/keepsakes.json`"), so the record can't silently stay uncommitted.
5. **Nothing is deleted.** The build writes over `public/seasons/`; an old version folder left from an earlier local build stays, unused (the index names one version per season). The deploy builds from a clean checkout, so it ships only current versions.
6. **Service worker.** `globIgnores: ['seasons/**']` keeps packs out of the precache (a player who never joins doesn't download them). Runtime caching: `seasons/index.json` network-first with a 3 s timeout, then the cached copy (so offline play still finds the joined season); every other file under `seasons/` cache-first (versioned paths never change). Both cache only status 200.
7. **`predev` and `prebuild`** run `build:seasons`, so `npm run dev` always has an `index.json` (ending T14.6's dev-only SPA-fallback error) and the Pages deploy (`npm run build` on main) ships the packs. CI's test job doesn't build; `sources.test.ts` gives the same validation in `npm test`.
