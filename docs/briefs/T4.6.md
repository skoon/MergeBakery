# Task T4.6: Save migrations

Context: Rise & Shine Bakery, a browser merge game (TypeScript, Vite, PixiJS, Vitest).
Read first: src/core/save.ts and src/core/save.test.ts (T4.5), docs/briefs/working-rules.md.

Goal: Give old saves a path forward: when the save format changes, a migration upgrades each old version step by step before validation.

Files to create or edit: src/core/migrate.ts, src/core/migrate.test.ts, src/core/save.ts, src/core/save.test.ts. Do not edit any other file.
Contract:

```ts
// src/core/migrate.ts
export type SaveObject = Record<string, unknown>;
/** Upgrades a save from version n to n + 1. Keyed by n. */
export type Migration = (save: SaveObject) => SaveObject;
/** The game's migrations. Empty while SAVE_VERSION is 1. */
export const MIGRATIONS: Readonly<Record<number, Migration>> = {};
/**
 * Applies migrations[v] for each v from save.version up to targetVersion − 1, setting
 * `version` to v + 1 after each. Returns the input unchanged when already at targetVersion.
 * Throws when save.version isn't a whole number, is newer than targetVersion, or a needed
 * migration is missing.
 */
export function migrate(
  save: SaveObject,
  targetVersion: number,
  migrations?: Readonly<Record<number, Migration>>,
): SaveObject;
```

In save.ts, `deserializeSave` calls `migrate(parsed, SAVE_VERSION)` after parsing JSON and before the zod validation; a thrown error becomes `{ ok: false, error }` with its message. Keep every existing save test passing.

The example migration lives in migrate.test.ts, not in `MIGRATIONS`: a v1 → v2 migration that renames a field (for example `state.coins` → `state.coinCount`) applied to a v1 fixture with an explicit `migrations` argument and target 2.

Rules: pure functions in src/core; no edits to types.ts; follow docs/briefs/working-rules.md.

Done when: `npx vitest run src/core/migrate.test.ts src/core/save.test.ts` passes, with tests for: the example v1 → v2 migration; a two-step chain (v1 → v3); an already-current save returned unchanged; a missing migration, a newer version, and a non-integer version each throwing; `deserializeSave` returning ok: false for a save whose migration throws. The checks in working-rules.md pass.
If the contract seems wrong, stop and explain instead of changing it.
