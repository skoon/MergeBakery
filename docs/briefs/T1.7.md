# Task T1.7: Data loader and validator

Context: Rise & Shine Bakery, a browser merge game (TypeScript, Vite, PixiJS, Vitest).
Read first: src/core/types.ts (all static data types and `GameData`), docs/briefs/phase-1-ids.md.

Goal: Load every JSON file in src/data, validate it with zod, check cross-references, and build the `GameData` lookup maps.

Files to create or edit: src/core/data.ts, src/core/data.test.ts, and stub data files src/data/customers.json (`{ "customers": [] }`) and src/data/chapter1.json (id `chapter1`, name "Grandma's Corner Shop", sceneKey `corner-shop`, introSceneId `null`, tasks `[]`). Create the two stubs only; T3.5 and T5.1 fill them later. Do not edit any other file.
Contract:

```ts
export interface RawGameData {
  items: unknown; // items.json
  generators: unknown; // generators.json
  recipes: unknown; // recipes.json
  ovens: unknown; // ovens.json
  economy: unknown; // economy.json
  customers: unknown; // customers.json
  chapters: readonly unknown[]; // chapter1.json, later chapters appended
  newGame: unknown; // newGame.json
}

/** Validates and builds GameData. Throws one Error listing every problem found. */
export function parseGameData(raw: RawGameData): GameData;

/** Imports the JSON files in src/data and calls parseGameData. */
export function loadGameData(): GameData;
```

- Write one zod schema per type and annotate each with its contract type, e.g. `const itemSchema: z.ZodType<Item> = z.object({ ... })`, so the schemas can't drift from types.ts. Objects are strict: unknown keys are errors.
- After the shapes pass, check cross-references and report every failure, not just the first:
  - Ids are unique within items, chains, generators, recipes, ovens, customers, chapters, and tasks within a chapter.
  - Every `chainId` names a chain; each chain's tiers run 1, 2, 3 … with no gaps or repeats.
  - Every referenced item id exists: spawn tables, rare drops, recipe inputs and outputs, customer favorites, task `featuredItems` and generator unlocks, and newGame items.
  - Every item in a `generator` chain has exactly one `GeneratorDef`, and every `GeneratorDef` names a generator item.
  - Weights in every spawn table and the rare-drop table sum to 100, and every weight is positive.
  - A recipe's output is the tier 1 item of a `baked` chain.
  - `collectReward` is non-null exactly for items in `bonus` chains.
  - Oven tiers run 1, 2, 3 … with no gaps; slots are at least 1.
  - `economy.levels` starts at level 1 with `xpTotal` 0, levels count up by 1, and `xpTotal` strictly increases; each `starsByItemCount` has length `maxItems`; `minItems` ≤ `maxItems`.
  - newGame cells lie inside `cols × rows`, no cell is used twice across `locks` and `items`, `chapterId` names a chapter, every oven id exists, and every `unlockedCustomers` id is a `regular` customer.
  - Task prerequisites name tasks in the same chapter; unlock ids (item, oven, customer) exist.
- Build `chainItems` with each chain's items sorted by tier.

Rules: pure functions in src/core; no new dependencies (zod is installed); no edits to types.ts. Other sessions are writing the other data files (items.json, generators.json, recipes.json, ovens.json, economy.json, newGame.json) at the same time. Never edit those files; if one is missing or fails validation when you finish, report which checks fail. Don't run git commands, `npm install`, or `npm run format`; format and lint only your files with `npx prettier --write <files>` and `npx eslint <files>`.

Done when: `npx vitest run src/core/data.test.ts` passes. The tests build a small valid fixture inline and show it parses; then, for each check above, a broken copy of the fixture fails with an error message naming the problem; and `loadGameData()` succeeds on the real data. `npx eslint` and `npx prettier --check` pass on your files.
If the contract seems wrong, stop and explain instead of changing it.
