# Task T3.3: Golden Whisk

Context: Rise & Shine Bakery, a browser merge game (TypeScript, Vite, PixiJS, Vitest).
Read first: src/core/types.ts (`ChainKind`, `Economy.goldenWhiskMaxTier`), src/core/drop.ts and src/core/drop.test.ts (T2.3 and T2.4), src/core/discovery.ts, src/core/testing.ts, docs/briefs/working-rules.md.

Goal: The Golden Whisk copies the item it is merged with.

Files to create or edit: src/core/drop.ts, src/core/drop.test.ts. Do not edit any other file.
Contract: `applyDrop`'s signature doesn't change. A whisk drop is when one of the two items (dragged or target) is in a `wildcard` chain and the other isn't:

- The other item must be in an `ingredient` or `baked` chain with tier ≤ `economy.goldenWhiskMaxTier` and not cobwebbed; otherwise reject 'notMergeable' (no swap).
- The whisk's cell becomes a copy of the other item (same `itemId`, not cobwebbed, `generator: null`); the other item stays where it is. The item is already discovered, so no `discovered` event. No XP.
- Event: `merged { itemId: <copied item>, cells: [<the whisk's cell>] }`.
- Two whisks dropped on each other follow the normal rules (they don't merge, so they swap).

The existing checks (same cell, locked, empty, dragging a cobwebbed item) still run first.

Rules: pure functions in src/core; no edits to types.ts; follow docs/briefs/working-rules.md. Keep every existing drop test passing.

Done when: `npx vitest run src/core/drop.test.ts` passes, with new tests showing: whisk onto a tier 5 item copies it; an item onto the whisk copies it too; tier 6 is rejected; generators, bonus items, and cobwebbed items are rejected; two whisks swap. The checks in working-rules.md pass.
If the contract seems wrong, stop and explain instead of changing it.
