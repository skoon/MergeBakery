# Task T5.8: Bottom nav bar and screen router

Context: Rise & Shine Bakery, a browser merge game (TypeScript, Vite, PixiJS, Vitest).
Read first: index.html, src/main.ts, src/ui/app.css, src/ui/tokens.css, src/ui/layout.ts and its test, src/ui/pantryDrawer.css, src/ui/kitchenSheet.css, src/ui/helpDialog.ts (a similar overlay), docs/briefs/working-rules.md.

Goal: A bottom bar switches between the board and full-height screens (Recipe Book, Bakery, Shop, Settings), so later tasks each have a place to put their screen.

Files to create or edit: src/ui/router.ts, src/ui/router.test.ts, src/ui/navBar.ts, src/ui/navBar.css, src/ui/layout.ts, src/ui/layout.test.ts, src/ui/app.css, src/ui/pantryDrawer.css, src/ui/kitchenSheet.css, index.html, src/main.ts. Do not edit any other file.

## Contract

```ts
// src/ui/router.ts — no DOM
export type ScreenId = 'board' | 'recipeBook' | 'bakery' | 'shop' | 'settings';

export interface Router {
  current(): ScreenId;
  /** Shows a screen. Showing the current screen does nothing and notifies no one. */
  show(id: ScreenId): void;
  /** Same as show('board'). */
  back(): void;
  /** Called after every change, with the new screen. Returns an unsubscribe function. */
  subscribe(listener: (id: ScreenId) => void): () => void;
}
/** Starts on 'board'. */
export function createRouter(): Router;

// src/ui/navBar.ts
export interface ScreenDef {
  id: Exclude<ScreenId, 'board'>;
  label: string;
  /** Builds the screen's contents into `container`. Called once, the first time the screen opens. */
  mount(container: HTMLElement): void;
}
export function mountNavBar(
  nav: HTMLElement,
  screensRoot: HTMLElement,
  router: Router,
  screens: readonly ScreenDef[],
): void;

// src/ui/layout.ts — add
export const NAV_HEIGHT = 56;
```

## Behavior

- **Nav bar:** a new `<nav id="nav">` at the very bottom of `#app`, below the tray, `--nav-height` (56 px) tall. Five equal buttons: Board, then one per `ScreenDef` in the order given. Each has `data-screen="<ScreenId>"` (the tutorial, T5.12, finds tabs by it). The current one has `aria-current="page"` and a highlighted style. Pressing a button calls `router.show`.
- **The Pantry stays in the tray.** It's a drop target for dragged board items, so it has to be on screen while the board is; that's why it isn't a nav tab even though the GDD lists it in the bottom bar.
- **Screens:** `<div id="screens">` in `#app`. Each screen is a panel filling the space between the HUD and the nav bar (the HUD stays visible), with a header holding its label and a Back button, and a scrolling body passed to `mount`. Only the current screen is visible; the board shows when the current screen is `'board'`. Escape goes back.
- **Layout:** the tray now sits above the nav bar. In app.css, `#tray` gets `bottom: var(--nav-height)`, and the Pantry drawer and Kitchen sheet anchor at `bottom: calc(var(--tray-height) + var(--nav-height))`. `computeBoardLayout` reserves `NAV_HEIGHT` below the tray, keeping the constant in step with the CSS variable as the file's header comment requires.
- **main.ts:** create the router and mount the nav bar with four screens. Until their tasks land, each `mount` writes a single "Coming soon" paragraph; T5.6 (Recipe Book), T5.3 (Bakery) and T5.9 (Settings) each replace one line. Shop stays "Coming soon"; the plan has no shop content yet.
- Use the tokens; fit a 320 px wide screen; the five labels must not wrap.
