# Task T3.1: Energy

Context: Rise & Shine Bakery, a browser merge game (TypeScript, Vite, PixiJS, Vitest).
Read first: src/core/types.ts (`EnergyState`, `Economy`, `GameData`), src/data/economy.json, docs/briefs/working-rules.md.

Goal: Compute energy from its stored value and timestamp, and spend or add it without losing partial regen progress.

Files to create or edit: src/core/energy.ts, src/core/energy.test.ts. Do not edit any other file.
Contract (all read `data.economy.energy`; regen period = `regenSec × 1000` ms):

```ts
/** Energy now. Regen adds 1 per full period since updatedAt, up to cap; a value at or above cap doesn't regen. A clock earlier than updatedAt gives the stored value. */
export function currentEnergy(
  data: GameData,
  energy: EnergyState,
  now: Timestamp,
): number;
/**
 * The same energy re-based to `now`. Below cap, updatedAt advances by whole periods only,
 * so partial progress toward the next point is kept. At or above cap, updatedAt becomes now.
 */
export function settleEnergy(
  data: GameData,
  energy: EnergyState,
  now: Timestamp,
): EnergyState;
/** Settles, then subtracts amount. Null when there isn't enough. */
export function spendEnergy(
  data: GameData,
  energy: EnergyState,
  amount: number,
  now: Timestamp,
): EnergyState | null;
/** Settles, then adds amount. May go above cap (energy jars). */
export function addEnergy(
  data: GameData,
  energy: EnergyState,
  amount: number,
  now: Timestamp,
): EnergyState;
/** Milliseconds until the next point, between 0 and one period. Null at or above cap. */
export function msToNextEnergy(
  data: GameData,
  energy: EnergyState,
  now: Timestamp,
): number | null;
```

Tests may build `GameData` with `loadGameData()` from src/core/data.ts.

Rules: pure functions in src/core; no edits to types.ts; follow docs/briefs/working-rules.md.

Done when: `npx vitest run src/core/energy.test.ts` passes, with tests for: partial regen (1.5 periods gives 1 point and keeps the half period); reaching cap; a value above cap staying put; a clock that goes backwards (no change); spending with and without enough energy; spending from cap starting regen at `now`; adding past cap; and `msToNextEnergy` counting down then returning null at cap. The checks in working-rules.md pass.
If the contract seems wrong, stop and explain instead of changing it.
