# Task T5.2: Completing renovation tasks

Context: Rise & Shine Bakery, a browser merge game (TypeScript, Vite, PixiJS, Vitest).
Read first: src/core/types.ts (`RenovationTask`, `Unlock`, `ActionResult`, `RejectReason`, `GameEvent`), src/core/orders.ts (`nextTask`), src/core/board.ts (`nearestEmpty`, `setCell`), src/core/discovery.ts (`discover`), src/core/testing.ts, src/data/chapter1.json (T5.1), docs/briefs/working-rules.md.

Goal: Spending stars on a renovation task marks it complete and applies its unlocks: a regular starts ordering, a generator appears, or an oven joins the Kitchen.

Files to create or edit: src/core/renovation.ts, src/core/renovation.test.ts. Do not edit any other file.

## Contract

```ts
// src/core/renovation.ts

/** The current chapter's task with this id. Throws when the chapter or task is unknown. */
export function taskById(
  data: GameData,
  state: GameState,
  taskId: TaskId,
): RenovationTask;

/** Incomplete tasks whose prerequisites are all complete, in chapter order. */
export function availableTasks(
  data: GameData,
  state: GameState,
): RenovationTask[];

/**
 * Throws for an unknown task (via taskById).
 * Rejects, in order:
 *   'alreadyCompleted'      the task is in completedTasks;
 *   'prerequisitesMissing'  any prerequisite isn't;
 *   'notEnoughStars'        stars < starCost;
 *   'boardFull'             a generator unlock would find no empty board cell and a full Pantry.
 *                           Checked before anything changes, counting every generator unlock
 *                           of the task, so a rejected task costs nothing.
 * Otherwise: subtracts starCost from stars, appends the id to completedTasks, then applies the
 * unlocks in order:
 *   generator  a new BoardItem { itemId, cobwebbed: false, full charges from its GeneratorDef,
 *              cooldownEndsAt: null } on nearestEmpty(board, the board's middle cell), else
 *              appended to the Pantry; then discover(itemId).
 *   oven       appends { ovenId, slots: slotCount × null } to kitchen.ovens.
 *   customer   appends customerId to unlockedCustomers unless already there.
 * Events, in order: for each generator placed on the board `spawned { itemId, cell, rare: false }`,
 * any `discovered` events from discover, then `taskCompleted { taskId }`.
 */
export function completeTask(
  data: GameData,
  state: GameState,
  taskId: TaskId,
): ActionResult;
```

The board's middle cell is `Math.floor(board.cells.length / 2)`, the same rule collected bakes use. `availableTasks(...)[0]` should equal `nextTask(...)` from orders.ts; import `nextTask` in the test to check this rather than duplicating it.

The phase-end review connects `completeTask` to the `completeTask` action in dispatch.ts; don't edit it.

## Tests

`src/core/renovation.test.ts`, with the real data and `stateWith` (set `stars`, `completedTasks` and `unlockedCustomers` through its overrides):

- `taskById` for a real task, and throwing for an unknown id;
- `availableTasks` on a new game (only `sweep-cobwebs`), after completing it (`wash-window` and `clear-counter`), and its first entry matching `nextTask`;
- completing `sweep-cobwebs`: stars down by 3, id recorded, one `taskCompleted` event;
- a customer unlock (`wash-window` adds `gus`), and not duplicating an already-unlocked customer;
- a generator unlock (`patch-roof`): a charged `dairy-fridge-1` on the empty cell nearest the middle, and a `spawned` event with that cell;
- a generator unlock with a full board going to the Pantry, and with a full board and a full Pantry rejecting `'boardFull'` with stars unchanged;
- an oven unlock (`second-oven`) adding an empty one-slot Toaster Oven;
- each reject reason, in the order above (for example, an already-completed task with too few stars rejects `'alreadyCompleted'`, not `'notEnoughStars'`);
- the input state is never mutated.
