# Task T14.6: Loading season packs at runtime

Context: Rise & Shine Bakery, a browser merge game (TypeScript, Vite, PixiJS, Vitest).
Read first: `implementation_plan.md` sections 1 and 2 (especially "Checking for new seasons", "Security" and "A save whose pack can't load"), `src/seasons/pack.ts`, `src/seasons/calendar.ts`, `src/core/save.ts`, `src/ui/saveStorage.ts`, `src/render/assets.ts`, `src/main.ts`, docs/briefs/working-rules.md.

Goal: at startup the game fetches the season catalog, loads the packs it needs (data and rules), merges them into GameData, and only then loads the save. A save whose season content can't be loaded still loads: it's backed up, the unloadable content is swept out, and the player is told. While the game runs it checks for new and updated seasons and offers a reload. No pack build (T14.7) and no season UI beyond the reload banner and the sweep notice (T14.8).

Branch: `t14.6-runtime-loading` (off `t14.5-rule-hooks`).

## The catalog: `BASE_URL/seasons/index.json`

T14.7 writes it; this task defines and reads it.

```json
{
  "seasons": [
    {
      "id": "thanksgiving",
      "name": "Harvest Supper",
      "version": "1.0.0",
      "window": { "start": "11-12", "end": "11-30" },
      "apiVersion": 1,
      "rules": true,
      "pngKeys": ["thanksgiving-pie-1"]
    }
  ]
}
```

A pack's files are at `BASE_URL/seasons/<id>/<version>/`: `season.json`, `rules.js` when `rules` is true, and `art/<spriteKey>.png` for each key in `pngKeys`, `.svg` for every other key. The URL is built from `id` and `version`, which must match the patterns `pack.ts` enforces, so an entry can't point outside `seasons/`. The index is fetched with `cache: 'no-cache'` so a new deploy is seen; pack files use versioned paths and normal caching.

## Rules

**Startup** (`loadSeasons`), before the save is read:

1. Fetch the index. If it's missing (HTTP 404), there are no seasons: `console.warn` and go on with the base data. Any other failure, or a file that isn't `{ seasons: [...] }`: `console.error` and go on with the base data.
2. Check each entry on its own. One with a bad id, version, window or shape, a duplicate id, or an `apiVersion` other than `SEASON_API_VERSION` is skipped with `console.error`.
3. Load an entry when its window, resolved with `resolveWindow(window, now, offsetAt)`, is open now, or when it is the season the save has joined (`peekSavedSeasonId`), even if its window has closed. Loading the save's season lets the next tick end it with the normal sweep, paying sell values and unclaimed milestones.
4. Fetch `season.json` and, if `rules`, import `rules.js`; the packs load in parallel. `parseSeasonPack(base, json)` validates the data, and its `id` and `version` must match the entry's. The rules module's default export must be an object with `apiVersion` equal to `SEASON_API_VERSION` and nothing besides the five hook names, each a function.
5. Merge the packs into GameData one at a time, in index order, with `withSeasons`, each with its window resolved from its own `season.json`.

A pack that fails any step is skipped with `console.error` naming the season, and the others still load. The result is `{ data, index, failed }`: the merged GameData, the valid index entries, and the `id@version` of each pack that failed.

**Timeout.** When the save hasn't joined a season (always true for a new player), loading gives up after 5 seconds: `console.warn`, and the game starts with the base data, an empty index and nothing failed, so the next check offers the open seasons through the banner. With a joined season there's no timeout, since giving up would sweep that season.

**Sweeping what can't load** (`sweepOrphanSeason`, run by `deserializeSave` before checking ids). Only the joined season's content is swept, meaning ids starting with `<seasonId>-`:

- **Its pack isn't loaded:** all of its content goes, and `season` is set to null. Unclaimed milestones aren't paid, there's no result card, and keepsakes already earned stay.
- **Its pack is loaded, but the save holds ids under its prefix the pack doesn't know** (an update renamed or removed them): just those go, and the season keeps running. If one of them was the season's generator, the player is left without it; pack updates mustn't rename the generator.

What goes, in either case:

- items on the board and in the Pantry, and oven bakes of the season's recipes, each paying `economy.seasons.orphanItemCoins`, generator included;
- seasonal orders (when the season ends) and any order asking for a swept item, and `lastSale` if it's one;
- entries in `discovered`, `pendingDiscoveries` and `rewardedChains`;
- staff assignments to swept chains or recipes, which are set back to idle.

The result says what happened: `{ seasonId, coins, ended }`, or null when nothing was swept. A save with no season, or whose season's content all loads, is unchanged, and any other unknown id still fails to load as today.

**Backup and notice.** When `deserializeSave` reports a sweep, `readSave` first copies the untouched save text to `rise-and-shine-save-preseason-<now>`, as it does for corrupt saves, then returns the swept save and the sweep. After startup `main.ts` shows a one-time card, using the season's name from the index, or its id when the index doesn't list it:

- ended: "<name> couldn't be loaded, so it has ended. Its items were sold for <coins> coins."
- not ended, coins above 0: "<name> was updated, and items it no longer has were sold for <coins> coins."
- not ended, 0 coins: no card.

**Art** (`registerSeasonArt`): `main.ts` registers every valid index entry, loaded or not, before the board is drawn. `assetUrl(key)` for a key starting with `<id>-` of a registered season returns `BASE_URL/seasons/<id>/<version>/art/<key>.png` if the key is in its `pngKeys`, `.svg` otherwise; when two ids match, the longer wins. Other keys resolve as today, and the `_missing` placeholder still covers a file that fails to load.

**Checking for new seasons** (`seasonBanner.ts`): every 30 minutes, and when the tab becomes visible again, the game refetches the index. `newSeasons` returns the open-window entries whose `id@version` is neither loaded (`data.seasons`) nor in `failed`, each marked `new` (its id isn't loaded) or `update` (a different version of a loaded season). When there are any and the tutorial is done, a small banner shows:

- one new: "<name> has arrived — tap to see it"
- one update: "<name> has been updated — tap to reload"
- several, any new: "New seasons have arrived — tap to see them"
- several updates: "Seasons have been updated — tap to reload"

Tapping writes the save and reloads the page. A fetch that fails during play is logged with `console.warn`, and nothing is shown.

## Decisions (Scott, Nov 9)

1. **The index entry has no `path`; packs come from this site only.** The URL is built from the checked `id` and `version`, so no index can load a file from outside `seasons/`.
2. **Art is registered for every season in the index**, so keepsakes show their art all year. Seasons are never removed from the index.
3. **The save's season is loaded even after its window closes**, so a player away for the last days gets the normal end.
4. **Back up, then sweep.** A sweep can't be undone in the game, so the untouched save is kept in localStorage first and can be restored by hand. Every swept item pays `orphanItemCoins` (5), the generator included.
5. **Unknown ids under the joined season's prefix are swept too**, even when its pack loads, so a pack update that drops an id can't make the whole save fail to load and start a new game.
6. **The player is told about a sweep** with a one-time card at startup.
7. **The banner offers new seasons and updates, with different wording**, after the tutorial only. A version that failed this session isn't offered again.
8. **A failed pack is skipped, not fatal**, with `console.error`. Loading times out after 5 seconds only when the save hasn't joined a season.

Carried to T14.7: write `index.json` in the format above, `{ "seasons": [] }` when there are no packs; keep every pack in the index; refuse to build a pack version that drops a keepsake's sprite key.
